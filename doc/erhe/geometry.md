# erhe_geometry

Stability: mostly stable

## Purpose
Polygon mesh geometry library built on Geogram. Provides a `Geometry` class wrapping
`GEO::Mesh` with typed attribute handling, mesh processing (normals, tangents, tex coords),
Conway polyhedron operators, subdivision (Catmull-Clark, sqrt3), CSG (experimental via
Geogram), and primitive shape generators.

## Key Types
- `Geometry` -- Main class wrapping `GEO::Mesh` with named attributes, connectivity queries, processing flags, and AABB computation.
- `Index_lists` -- Compressed index lists keyed by an element index (offsets + one flat index array), built in two passes (count, then add in the same order). `Geometry` keeps its vertex-to-corners, vertex-to-edges and edge-to-facets tables in this form and `get_vertex_corners()` / `get_vertex_edges()` / `get_edge_facets()` return a `std::span<const GEO::index_t>` into them, valid until the next `update_connectivity()` / `build_edges()`. A `std::vector` per vertex made `process()` heap-bound: with many worker threads processing meshes at once (editor brush build, async mesh operations) the per-vertex allocations dominated and contended on the heap.
- `Mesh_attributes` -- Typed wrappers (`Attribute_present<T>`) for all standard vertex/corner/facet attributes (normals, tangents, tex coords, colors, joint data, IDs).
- `Attribute_present<T>` -- Binds a `GEO::Attribute<T>` with a presence flag per element.
- `Attribute_descriptor` -- Describes an attribute's name, transform mode, and interpolation mode.
- `Geometry_operation` -- Base class for operations that transform a source geometry into a destination. `post_processing()` ends with `propagate_edge_sharpness_identity()`, which carries `edge_sharpness` to each destination edge whose two vertices derive with weight 1 from the two vertices of one source edge (`doc/erhe/subdivision_crease_edges.md`, "Which operations carry creases").
- `Mesh_info` / `Mesh_serials` -- Statistics and change-tracking for mesh data.

## Public API
- `Geometry(name)` then `geometry.process(flags)` -- Create and process a mesh.
- `geometry.get_mesh()` -- Access the underlying `GEO::Mesh`.
- `geometry.get_attributes()` -- Access typed attribute wrappers.
- Shape generators: `shapes::make_box()`, `shapes::make_sphere()`, `shapes::make_capsule()`, `shapes::make_torus()`, `shapes::make_cone()`, `shapes::make_disc()`, `shapes::make_icosahedron()`, etc.
- Conway operators: `ambo`, `chamfer`, `dual`, `gyro`, `join`, `kis`, `meta`, `subdivide`, `truncate`.
- Subdivision: `catmull_clark_subdivision`, `sqrt3_subdivision`.
- CSG: `difference`, `intersection`, `union_` (experimental).
- Utilities: `compute_facet_normals()`, `compute_mesh_tangents()`, `triangulate()`, `normalize()`, `reverse()`, `bake_transform()`.
- Convex hulls: `make_convex_hull(const GEO::Mesh& source, GEO::Mesh& destination)` and `shapes::make_convex_hull(GEO::Mesh& mesh, const std::vector<glm::vec3>& points)` (the latter delegates to the former). Both return `false` for a point set that spans no volume; see the convex hull note below.
- Topology walkers (`erhe_geometry/topology.hpp`): `walk_edge_loop()`, `walk_edge_ring()`, `walk_face_loop()`, `walk_boundary_loop()` and `walk_connected_region()` follow the Blender selection rules stated in `doc/plans/mesh_modeling.md` section 4.1. They require a `Geometry` processed with `process_flag_connect | process_flag_build_edges`, take a seed edge (seed vertices for the connected region), and fill a caller-owned vector (cleared, capacity kept) end to end: edge indices, facet indices for the face loop, vertex indices in flood order for the connected region. A closed loop or ring (`Walk_shape::closed`) lists each element once, starting at the seed. `Edge_loop_delimit` (`crease`, `outer_corners`) and `Region_delimit` (`crease`, `winding`) select where a walk stops; an edge is a crease when its `edge_sharpness` is above 0. An interior seed edge with an end vertex of valence 3 and three facets has a hub when its largest facet has more than four corners: the loop then follows that facet's edges through valence-3 vertices, stopping at a missing, visited or boundary edge (a cap edge of a pentagonal prism loops around the pentagon); without a hub a valence-3 vertex ends the loop. Visited sets live in per-thread scratch, so a steady-state walk allocates nothing.
- `Edit_mesh` (`erhe_geometry/edit_mesh.hpp`) -- A mutable polygon mesh scratch on which modeling operations compose local edits (`doc/plans/mesh_modeling.md` D2). `load()` copies a `Geometry` with edge connectivity: vertices (position, provenance as weighted source vertices), facets (corners with provenance as weighted source corners, one source facet), edges keyed by their canonical vertex pair (facet list, optional sharpness, wire edges allowed) and per-vertex facet and edge lists. Deleted elements are tombstoned, so handles stay valid until emission. The primitives, each keeping the adjacency current: `split_edge(edge, t)` (a new vertex and corners weighted `1 - t` / `t` on the edge's first / second vertex), `split_facet(facet, corner_a, corner_b)`, `split_facet_edgenet(facet, edges)` (chords and chains through interior vertices added with `add_vertex()`; dangling edges are dropped; a floating island is connected to the boundary by two non-crossing edges from its nearest vertex pairs, so no facet repeats a vertex; interior corners take mean value coordinate weights of the facet's corners), `join_facets(region)` / `join_facet_pair(edge)` (an edge-connected region with one manifold boundary loop, else a `Join_result` failure and no change), `collapse_vertex(v)` (two edges joined, sharpness the larger), `weld_vertices(merges)` (the weld core of the plan's section 4.4), `separate_vertex(v, edges)` (rip into one vertex per fan), `delete_elements(elements, Delete_context)` (the five contexts of section 4.3), `create_facet(vertices, reference_facet)`, `create_facet_from_corners(corners, source_facet)` (explicit corner provenance), `set_facet_vertices(facet, vertices)` (moves a facet's corners onto other vertices, removing the edges left without facets), `set_corner_sources(facet, corner, sources)` and `reverse_facet(facet)` (the corners in the opposite order, the first corner first, each corner keeping its vertex and provenance). The free functions `compute_mean_value_weights()` and `compute_newell_normal()` are the polygon helpers the primitives use.
- `operation::Geometry_operation::remap_component_selection(src, dst)` -- Carries a component selection through a built operation: a facet maps to the destination facets whose provenance names it, a vertex to its destination image, an edge to the destination sub-edges along it (endpoint images and inserted split vertices), each sub-edge kept only when the destination has that edge (when the destination has an edge table), so a merged or dissolved edge is not reported while its surviving endpoints are.
- `operation::Edit_mesh_operation` -- A `Geometry_operation` holding an `Edit_mesh` loaded from its source. A subclass's `build()` runs primitives on `m_edit_mesh` and calls `emit()`, which writes the live elements into the destination (one `create_vertices(n)`, one polygon per facet) and records every vertex, corner and facet provenance, so attributes interpolate from the source and `remap_component_selection()` maps a source vertex to the destination vertex whose provenance is that vertex with weight 1 and a source facet to the destination facets carrying it. The scratch positions are written after interpolation, the destination is processed with `structural_post_process_flags`, then each scratch edge's sharpness is written to its destination edge. A wire edge has no destination edge; a loose vertex is emitted.
- Delete and dissolve (`erhe_geometry/operation/dissolve.hpp`, `doc/plans/mesh_modeling.md` section 4.3), each an `Edit_mesh_operation` taking a source selection and an optional `Component_remap`: `delete_components(source, destination, selection, Delete_context)` deletes the vertices, edges or facets of the selection per `Edit_mesh::delete_elements()`; `dissolve_faces(..., selected_facets, Dissolve_faces_options{dissolve_vertices})` joins each edge-connected group of selected facets (a group whose join fails stays) and optionally collapses the vertices the joins left with two edges; `dissolve_edges(..., selected_edges, Dissolve_edges_options{dissolve_vertices, preserve_quads, angle_threshold_degrees, face_split})` joins the facet pair of each selected manifold edge, then collapses end vertices left with two edges whose edge angle is below the threshold, except a vertex with more than one selected edge that touches an unselected facet and, with `preserve_quads`, the corners of a triangle pair; `dissolve_vertices(..., selected_vertices, Dissolve_vertices_options{face_split, boundary_tear})` joins the facet pairs around each selected vertex with three or more edges, collapses it when two edges remain and deletes it when none do (`face_split` first splits off its corner in each surrounding facet, `boundary_tear` separates a boundary vertex into one vertex per facet and collapses each); `dissolve_limited(..., selection_or_nullptr, Dissolve_limited_options{angle_limit_degrees, dissolve_boundaries, delimit_winding, delimit_crease})` joins manifold edges in increasing dihedral angle below the limit, re-scoring the joined facet's edges, then collapses two-valent vertices in increasing edge angle below the limit whose collapse keeps every adjacent corner convex. The edge angle of a two-valent vertex is the plain angle between its two edges (0 when collinear).
- Merge (`erhe_geometry/operation/merge_vertices.hpp`, `doc/plans/mesh_modeling.md` section 4.4), each an `Edit_mesh_operation` that maps vertices to survivors and runs `Edit_mesh::weld_vertices()`, taking an optional `Component_remap` (the survivor is selected when any vertex of its cluster was): `merge_vertices(source, destination, selection, Merge_vertices_options{type, position, merge_uvs})` merges the selection's vertices (with the endpoints of its edges and the vertices of its facets) - `Merge_type::at_center` / `at_position` keep the lowest selected vertex, moved to the mean or to `position` (mesh-local), `at_first` / `at_last` keep the lowest / highest selected vertex index in place (a selection has no history order), `collapse` merges each connected island of the selected edges (the selection's edges, its facets' edges, the edges between its vertices) into the island's lowest vertex at the island mean; at center, at position and collapse give the survivor the whole cluster as provenance with equal weights, so vertex attributes average, the others list the other members with weight 0; `merge_uvs` writes the midpoint of the per-component extent of the merged vertices' source corner texcoords to every corner of the survivor (per channel, per island). `merge_by_distance(source, destination, selection_or_nullptr, Merge_by_distance_options{threshold, use_centroid, include_unselected})` clusters the selected vertices (every vertex for `nullptr`) with the in-tree octree radius search (`operation/octree.hpp`) into connected components of the strictly-closer-than-threshold relation; a pair keeps the lower index, a larger cluster the vertex nearest its centroid; `use_centroid` moves the survivor to the cluster mean and averages the vertex attributes; `include_unselected` lets unselected vertices join a selected vertex's cluster, and then the survivor is chosen among them and stays in place. `Edit_mesh::set_vertex_sources()` and `Edit_mesh_operation::get_emitted_vertex()` serve these operations.
- Subdivide edges (`erhe_geometry/operation/subdivide_edges.hpp`, `doc/plans/mesh_modeling.md` section 4.5), an `Edit_mesh_operation`: `subdivide_edges(source, destination, selected_edges, Subdivide_edges_options{cuts, smoothness, only_quads}, result, remap)` splits every selected edge (source vertex pairs) `cuts` times at `(k + 1) / (cuts + 1)` and fills each facet by the pattern of its split edges, recorded before the splits: a quad with two opposite split edges connects the cuts pairwise, two adjacent ones nest around the shared corner plus one corner-to-corner edge, three connect the opposite pair and join the middle edge's cuts to the nearer end of the last connecting edge (quads and triangles, no new vertex), four build a `(cuts + 2)` vertex grid (interior vertices on the Coons patch of the four runs, bilinear provenance over the corners, split with `split_facet_edgenet()`); a triangle with one split edge fans the cuts to the opposite corner, with three builds a triangular lattice; any other facet with two split edges connects the two runs pairwise; a facet whose split edges meet collinearly, or a non-quad under `only_quads`, keeps the new vertices on its boundary. `smoothness` moves each cut toward a cubic Hermite curve whose end tangents are the edge projected onto the endpoints' tangent planes (source vertex normals, else facet-averaged). The optional `Subdivide_edges_result` lists the inner elements in destination indices (cut and interior vertices, the edges the fills created, the facets a fill split); the remap maps a selected edge to its split halves (the cut vertices are registered as the edge's split midpoints). `get_selection_edges()` derives the edge set from a `Geometry_component_selection` of any mode.
- Inset faces (`erhe_geometry/operation/inset_faces.hpp`, `doc/plans/mesh_modeling.md` section 4.8), an `Edit_mesh_operation`: `inset_faces(source, destination, selected_facets, Inset_faces_options{boundary, even_offset, relative_offset, edge_rail, thickness, depth, outset, individual, interpolate}, result, remap)`. Region mode detaches the region (the selected facets; outset: the others) along its boundary edges (an edge to a facet outside the region, or a mesh boundary edge while `boundary` is on): every fan of region facets around a boundary vertex gets its own inset vertex (so a pinch gets one per fan, and the facets outside keep the original vertex), each boundary edge gets a rim quad, and an inset vertex moves along the normalized sum of its fan's boundary edge tangents (even offset: scaled by `1 / cos(half angle)`; edge rail: along the fan's one interior edge; one boundary edge: along the unsplit mesh boundary edge, flush) or, with relative offset, further scaled by the mean boundary edge length; depth moves every region vertex along its facets' averaged normal times the shell factor. Individual mode gives each selected facet its own vertices and a rim quad per edge, depth along the facet normal. Interpolate re-samples the moved corners' provenance by mean value coordinates in the pre-move facet; rim facets take the region facet as source facet (outer corners its pre-move corners, inner corners its moved ones). `Inset_faces_result` lists, in destination indices, the inset vertices with their scaled thickness and depth directions (so a caller can place them for any thickness and depth), the inset facets and the rim facets; the remap maps the selection to the inset facets without the rim facets. A region without boundary edges is left unchanged.
- Bevel edges (`erhe_geometry/operation/bevel_edges.hpp`, `doc/plans/mesh_modeling.md` section 4.9, M13a and the segments and profile of M13b), an `Edit_mesh_operation`: `bevel_edges(source, destination, selected_edges, Bevel_edges_options{offset_type, amount, loop_slide, segments, profile}, result, remap)` bevels the selected edges (source vertex pairs); a boundary or non-manifold edge, or an edge at a vertex whose facets are not one fan, is skipped with a warning. Around each bevel vertex the fan is ordered counter-clockwise; each beveled edge has an offset line in each of its two facets (offset type `offset`: at the amount; `width`: at `amount / (2 sin(phi / 2))`, phi the angle between the edge's two in-facet perpendiculars). The wedges between two consecutive beveled edges share one new vertex: the meet of the two offset lines in their shared facet, on the one unbeveled edge between them with loop slide (the mean of where the offset lines come closest to it), else the midpoint of the offset lines' closest approach; an open fan's end span slides onto the unbeveled edge next to the beveled one, and a closed fan with one beveled edge gets a new vertex on every other edge (the two neighbours where the offset lines reach them, the rest at the amount along the edge). Every facet around a bevel vertex is rebuilt with that corner replaced by its wedge's chain of new vertices, each beveled edge becomes a quad (edge facet), three or more new vertices of one bevel vertex form a vertex facet, and the bevel vertices go. Corners interpolate the facet's original corners (linearly along the edge a new vertex lies on, else mean value coordinates); edge facets copy the original corners at their ends, vertex facets average the corners at the vertex. With `segments` n > 1 each end of a beveled edge gets a profile of n + 1 samples between its two boundary vertices B_r and B_l: with V the bevel vertex and (x, y) on the unit superellipse |x|^r + |y|^r = 1 (r = 1 / (1 - profile): 0 the straight chamfer, 0.5 the quarter circle about C = B_r + B_l - V, 1 the square corner along the original facets), spaced evenly by arc length and symmetric, sample k sits at V + (1 - y)(B_r - V) + (1 - x)(B_l - V). Each beveled edge becomes a strip of n quads; a rebuilt facet holding both ends of a profile gains its samples; two beveled edges at a closed fan share one profile; a vertex facet with fewer than three beveled edges (or on an open fan) gains the samples along its sides; three or more on a closed fan get the cutoff patch (a centre facet at the middle sample of every side, both middle samples for odd n, and per boundary vertex one triangle plus n / 2 - 1 quads up to it). Blender's adjacent-pattern grid fill (ADJ), offset adjustment, clamp overlap, vertex bevel and miters are not built. Edge sharpness: the beveled edge's is dropped, the new edges carry none, and an unbeveled ring edge a boundary vertex lies on keeps its sharpness on the shortened edge. `Bevel_edges_result` lists, in destination indices, the new vertices (profile samples included) with their directions per unit amount (every rule is linear in the amount, so a caller places them for any amount at fixed topology), the edge facets (n per beveled edge), the vertex facets (the patch facets included) and the beveled edge count; the remap selects the edge facets with their edges and vertices.
- Split, rip and separate (`erhe_geometry/operation/split_components.hpp`, `doc/plans/mesh_modeling.md` catalog M9), each an `Edit_mesh_operation` that never moves a position; a duplicated vertex copies its vertex's provenance and a duplicated edge keeps its sharpness. `get_selection_facets()` derives the facets of a selection of any mode (the selected facets, the facets whose vertices or edges are all selected). `split_facets(source, destination, selection, remap)` disconnects those facets: each vertex shared by a region facet and an outside facet is duplicated and the region moves onto the copy; the remap selects the region in the source selection's sets. `rip_vertices(source, destination, selection, Rip_options{direction}, remap)` tears the selection's vertices (or its edges' endpoints) along the cut (its edges and the edges between two selected vertices) into one vertex per fan (the `separate_vertex()` rule); a vertex whose cut does not split its facets is cut further, one uncut manifold edge at a time, along the edge's continuation at a run end or along the edges nearest to `direction` at a vertex without cut edges. The ripped side is the facet traversing each cut edge in the walk direction of its run (walked from the lowest end vertex), or the side toward a non-zero `direction`; ripped fans get new vertices, and the remap selects the ripped vertices and the ripped copies of the cut edges. `split_edges(source, destination, selected_edges, remap)` is that tear on an edge set without a direction. `extract_facets(source, kept, extracted, selected_facets, kept_remap, extracted_remap)` writes two results: the source without the facets (`Delete_context::faces`) and the facets alone with their vertices.
- Fill (`erhe_geometry/operation/fill.hpp`, `doc/plans/mesh_modeling.md` section 4.10, catalog M15), an `Edit_mesh_operation`: `fill_selection(source, destination, selection, Fill_result*, remap)` reads a selection of any mode (its vertices, its edges plus the edges between selected vertices, the facets of `get_selection_facets()`); only edges with fewer than two facets take part. The first case that creates anything wins: two vertices joined by the shortest boundary-edge chain between them become one n-gon (a Geometry holds no wire edges, so the edge is made only when it closes a facet; without a chain there is nothing to fill); one free vertex plus one open chain become one n-gon; edge cycles become n-gons, after one open chain is closed or two are joined end to end the way with the larger area vector (no bow-tie), else a branching net is filled by the shortest directed cycle through each edge, traversing it opposite to its facet; selected facets join per edge-connected group; three or more vertices sorted by angle in their least squares plane become one n-gon. A new facet's winding follows the shared edges' facets (majority vote, a tie by the adjacent facets' mean normal), its corners copy a neighbouring facet's corner at each vertex and its facet provenance is a neighbour's. `Fill_result` lists the new destination facets and whether anything was filled; the remap selects the new facets with their vertices and edges. Grid fill is not implemented.
- Connect vertex path (`erhe_geometry/operation/connect_vertices.hpp`, `doc/plans/mesh_modeling.md` section 4.10, catalog M16), an `Edit_mesh_operation`: `connect_vertices(source, destination, selected_vertices, remap)` splits each facet (`Edit_mesh::split_facet()`) between consecutive selected corners, skipping a corner whose two neighbours are both selected and dropping a pair of adjacent corners, a chord whose midpoint lies outside the facet (Newell-plane projection) and a chord crossing an earlier one. `connect_vertex_pair(source, destination, a, b, remap)` joins two vertices without a shared facet: a best-first search by accumulated length over the vertices on, and the edges crossed by, the plane through both vertices containing their mean vertex normal (projected perpendicular to the line; another perpendicular when it vanishes), then the crossed edges are split at the plane and consecutive path vertices connected. `connect_selection()` picks the pair form for exactly two vertices sharing no facet. The remaps select the new edges, the selected vertices and the inserted ones.
- Bridge edge loops (`erhe_geometry/operation/bridge_loops.hpp`, `doc/plans/mesh_modeling.md` section 4.10, catalog M14), an `Edit_mesh_operation`: `bridge_loops(source, destination, selection, Bridge_loops_options{connection, merge, merge_factor, twist_offset, cuts}, Bridge_loops_result*, remap)`. Selected facets are deleted and the boundaries of the deleted regions are the loops; otherwise the selected edges plus the edges between selected vertices. A loop vertex with more than two loop edges, a loop edge with two facets, fewer than two loops, or merge with unequal loops leave the source unchanged (logged). Loops are ordered by proximity and paired per `Bridge_connection` (`open_loop` 1-2, 2-3, ...; `closed_loop` also the last to the first; `loop_pairs` 1-2, 3-4, ...). The second loop of a pair is flipped by the end-to-end direction (open) or by the side of the vector between the centres its normal faces (closed); when that is indecisive, so that the facets along the two loops run opposite relative to the pairing. Closed loops take the rotation minimizing the summed rung lengths, plus the twist. Unequal counts repeat entries of the shorter loop (doubled while within the longer count, the rest spread evenly), the strip of triangles is beautified by exchanging a rung between two neighbouring single-loop steps when that shortens it, and neighbouring steps of the two loops join into quads. The winding is a vote over the loop edges (opposite to the facet that had each edge), corners copy that facet's corner on the same loop edge, and a facet that would repeat a facet or give an edge a third facet is skipped (so a plain cube's opposite faces bridge nothing). Merge welds each pair at `lerp(a, b, merge_factor)` through `Edit_mesh::weld_vertices()`. Cuts run `subdivide_edges()` on the rungs of the bridged result. `Bridge_loops_result` lists the destination bridge facets; the remap selects them with their vertices and edges (merge: the welded vertices and the edges between them).
- Flip and recalculate normals (`erhe_geometry/operation/flip_facets.hpp`, `doc/plans/mesh_modeling.md` catalog M10), an `Edit_mesh_operation` that only reverses facets (`Edit_mesh::reverse_facet()`), so every vertex, edge and facet index carries over and the remap keeps the selection: `flip_facets(source, destination, selected_facets, remap)` reverses the selected facets; `recalculate_facet_normals(source, destination, selected_facets, Normal_side, remap)` (an empty set: every facet) orients each region of those facets connected through edges with two facets: the facet farthest from the region's area-weighted centre along its own normal line faces away from the centre, and the winding propagates across the shared edges (a neighbour running a shared edge in the same direction as its oriented facet is flipped); `Normal_side::inside` inverts the region. A flipped facet's corner normals are negated, a vertex whose facets are all flipped has its vertex normal negated, and smooth vertex normals are recomputed. Smooth vertices (`erhe_geometry/operation/smooth_vertices.hpp`): `smooth_vertices(geometry, selected_vertices, Smooth_vertices_options{factor, repeat}, out_positions)` computes, without changing the geometry, the positions of the selected vertices (in set order) after `repeat` iterations that each move a vertex by `factor` toward the average of its edge-connected neighbours from the start of the iteration.
- Knife (`erhe_geometry/operation/knife_cut.hpp`, `doc/plans/mesh_modeling.md` section 4.7), an `Edit_mesh_operation` the knife tool drives point by point: `Knife_cut(source, destination, Knife_view, Knife_options{cut_through, close_polyline, vertex_tolerance_px, edge_tolerance_px, facet_tolerance_px})`, `add_point(Knife_point)`, `end_polyline()`, `close_polyline()`, `undo_last_point()`, `get_preview_segments()` and `finish(result, remap)`; `knife_cut(source, destination, view, points, options, result, remap)` is the one-shot numeric path. `Knife_view` holds, in mesh-local space, `clip_from_mesh` (a column-vector clip transform), the viewport size in pixels, the eye position and the view direction and whether the view is perspective, so the operation projects to pixels itself. A `Knife_point` is a mesh-space position snapped (`Knife_snap`) to a vertex, an edge (a vertex pair) or a facet. Each segment between consecutive points finds its hits on the cut plane through both points and the eye (perspective) or the view direction (orthographic): the two points, the vertices within `vertex_tolerance_px` of the screen segment, and the crossings of the edges of the facets straddling the plane that project onto the segment away from its ends; without `cut_through` a hit other than the two points is kept only when the ray from it toward the eye crosses no facet of the mesh that does not contain it. Hits sort along the segment (then by depth) and merge per element; per facet, consecutive hits of the facet become a cut edge unless they are one cut vertex, lie on one original edge, or their midpoint is outside the facet (concave facets), and a cut edge crossing an earlier one of the same facet splits both at a new facet point. Points form polylines: `end_polyline()` makes the next point start a new polyline (the earlier cut edges stay), `close_polyline()` adds the segment from the current polyline's last point back to its first (three points or more) and ends it, `Knife_options::close_polyline` closes the current polyline at `finish()`, and `undo_last_point()` drops the last point and replays the rest (a polyline keeping points is open again; after a polyline's only point the next point starts a new one). Nothing touches the scratch before `finish()`, which splits each original edge at its cut points in parameter order, adds each facet point as a vertex (mean value coordinate provenance), splits each cut facet with `split_facet_edgenet()` (islands joined by two connecting edges, dangling edges dropped), deletes facet points left without edges, collapses edge points left without a cut edge, and emits. `Knife_result` lists the new vertices and the destination edges along the cut; the remap maps a selected facet to its pieces and a selected edge to its halves.
- `Geometry::get_corner_edge(corner)` -- The edge of the facet edge starting at `corner` (the corner's vertex to the next corner's vertex), valid until the next `build_edges()`.
- `get_vertex_corners(vertex)` is in fan order: consecutive corners share an edge at the vertex, stepping from a corner to the one across its incoming facet edge. A boundary vertex's corners run from the corner whose outgoing facet edge is a boundary edge to the corner whose incoming facet edge is one.

## Notes
- All mesh data lives in Geogram's `GEO::Mesh`; erhe wraps it with typed accessors.
- Conversion helpers exist between `glm` and `GEO` vector/matrix types.
- Attribute interpolation during operations uses weighted source tracking per destination element.
- **Hand-building a `GEO::Mesh`** (rather than producing one through the geometry operations) has two requirements that are easy to miss, both of which fail far from the cause:
  - End with `mesh.vertices.set_single_precision()`. The primitive builder reads points through `get_pointf()`, and leaving the mesh in double precision trips a geogram assertion.
  - A hand-built mesh carries NO normal attribute, and the primitive builder writes vertex normals from `facet_normal`. Call `compute_facet_normals()`, or anything shading with `dot(V, N)` renders flat black.
- **Convex hulls need four affinely independent points.** `make_convex_hull()` classifies its input with `erhe::math::classify_affine_span()` before reaching Geogram and returns `false` with a `log_geometry` warning naming the reason (fewer than 4 points / all points coincide / collinear / coplanar). Callers treat `false` as "this geometry has no hull": the collision shape is simply left absent. The guard is what keeps degenerate input out of Geogram's Delaunay, where a volume-less point set is a warning plus a garbage triangulation on the sequential path and an unbounded hang on the parallel one.
- Facet winding is counter-clockwise seen from outside. Check a facet with the cross product rather than trusting a comment: for facet `{a, b, c}`, `(v_b - v_a) x (v_c - v_a)` must point away from the interior. Reversed winding normals a closed shape inward -- it renders inside out *and* the raytrace hit normal comes back negated.
